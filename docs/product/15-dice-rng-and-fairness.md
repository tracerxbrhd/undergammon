# 15. Dice RNG and Fairness

## Product principle

Dice are random. UNDERGAMMON must never alter dice outcomes based on player skill, rating, win streak, match state, game mode, AI difficulty, monetization status, retention goals, or any other product factor.

## Authoritative dice flow

- The player explicitly presses the roll action; there is no automatic roll.
- The backend generates the dice result at that moment using a cryptographically secure random source.
- The generated result becomes authoritative server state and is persisted in the technical match log.
- Clients receive the authoritative values and only render/animate them.
- Mini App, Bot, AI, and other clients cannot choose, reroll, replace, bias, or reinterpret an authoritative result.

## Applies to every mode

The same neutral RNG rules apply to:

- Ranked PvP
- Casual PvP
- Private matches
- AI matches

AI difficulty changes only decision quality. It never changes dice probability.

## Explicitly forbidden

The system must not implement hidden mechanics such as:

- better rolls for new players;
- worse rolls for players on a win streak;
- comeback dice for a losing player;
- stronger rolls for Hard AI;
- different probabilities by rating or season;
- monetized or cosmetic advantages affecting RNG.

## Transparency

The product may explicitly communicate that dice are generated by the server and are independent of rating, streaks, mode, and opponent.

A public cryptographic seed/reveal or verifiable-dice proof system is not required for the first release. It may only be reconsidered later if there is real product demand.

## Dice history

The first release does not expose a player-facing dice-history panel in the match HUD.

The backend still keeps authoritative technical records of generated rolls for debugging, incident investigation, and match integrity checks. This technical logging is not a replay feature and does not imply that user-facing replay support will be implemented.
